---
title: Compliance Officer overview
description: The compliance officer's view of Spctre — key screens and their purpose.
---

As a Compliance Officer, you use Spctre to read, verify, and export evidence of AI agent governance. You don't author policies or handle live escalations — your focus is on compliance posture, audit evidence, and providing attestation to external auditors.

## Your key screens

| Screen | Purpose |
|---|---|
| **Audit → Audit package → Overview** | Package readiness, governance posture, and the next action before external handoff |
| **Audit → Audit package → Audit package** | Package contents, control mappings, verification detail, seals, and exports |
| **Audit → Audit package → Evidence & retention** | Policy lifecycle, linked evidence, and retention decisions |
| **Audit → Audit package → Delivery** | GRC delivery health and integration handoff status |
| **Audit → Decision evidence** | Recorded agent decisions, policy matches, and simulations |
| **Audit → Change ledger** | Hash-chained platform changes, including logins, config changes, and bundle publishes |
| **Cost → Cost & Usage** | Token and cost summaries for budget compliance |

## What you can do

| Action | Where |
|---|---|
| Determine whether a package is ready | **Audit → Audit package → Overview** |
| Inspect and export the audit package | **Audit → Audit package → Audit package** |
| Generate a compliance seal | **Audit → Audit package → Audit package** → **Generate seal** |
| Trace lifecycle and retention evidence | **Audit → Audit package → Evidence & retention** |
| Review GRC delivery health | **Audit → Audit package → Delivery** |
| Trace a specific decision | **Audit → Decision evidence** → search by decision ID |
| Read the platform change history | **Audit → Change ledger** |
| Interpret the cost & usage dashboard | **Cost → Cost & Usage** |

## What you cannot do

Compliance Officers have read-only access to all governance data. You cannot author policies, approve branches, or resolve escalations. If you find a compliance gap that needs a policy fix, raise it with your Policy Creator or workspace admin.

## Where to start

If you're preparing for an audit, begin on **Audit → Audit package → Overview**. Resolve its highest-priority readiness check, then use **Audit package** to seal or export the evidence. Use **Evidence & retention** when a reviewer needs the lifecycle record behind the package.
