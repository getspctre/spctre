A **pack** is a versioned, curated bundle of rules for a specific connector or governance use case. Packs make it easy to distribute and reuse governance logic across workspaces and tenants.

## Pack fields

| Field | Description |
|---|---|
| `id` | Unique identifier, e.g. `stripe-payments-v1` |
| `name` | Display name |
| `connector` | Target connector identifier |
| `description` | Governance purpose |
| `riskLevel` | `LOW`, `MEDIUM`, or `HIGH` |
| `tags` | Topic tags, e.g. `["payments", "refunds"]` |
| `domains` | Policy domains |
| `rules` | Array of rule summaries |
| `metadata.version` | Semantic version, e.g. `1.2.0` |
| `metadata.author` | Pack author |
| `metadata.minimumApprovals` | Number of reviewers required to publish |
| `metadata.compatibilityTargets` | Frameworks this pack is designed for |
| `metadata.changelog` | Array of `{ version, date, summary }` entries |

## Scaffolding a pack

Use the CLI to generate a new pack template:

```bash
spctre pack scaffold my-connector \
  --connector my-connector \
  --version 1.0.0 \
  --output ./packs/my-connector
```

This creates a directory with a pack manifest and starter rule files.

## Publishing a pack

1. Write your rules inside the pack directory
2. Attach the pack to a policy branch in the control plane
3. Meet the `minimumApprovals` threshold
4. Publish the branch — the pack rules are included in the next bundle

## Built-in packs

| Pack | ID | Purpose |
|---|---|---|
| Simulation Guidance Governance | `spctre-agent-governance-v1` | Spctre-managed baseline for human decision boundaries and auditable inline simulation guidance |
| Trust Governance | `trust-governance-v1` | Trust score and context budget enforcement |
| Gateway · Portkey | `gateway-portkey-v1` | Portkey gateway integration |
| Gateway · Helicone | `gateway-helicone-v1` | Helicone gateway integration |
| Gateway · LiteLLM | `gateway-litellm-v1` | LiteLLM gateway integration |
| Gateway · Notion | `gateway-notion-v1` | Notion orchestration governance |

See [Trust Governance Pack](/help-docs/developer/policies/trust-governance) for the full rule set in `trust-governance-v1`.

The Simulation Guidance Governance Pack is published to each workspace as part of the
initial policy baseline. It is connector-scoped to `spctre-agent`, so it
composes with, rather than replaces, customer organization baselines. Its rules
are maintained by Spctre and are excluded from stale and unused-rule cleanup
analysis.

The `spctre-agent.*` stable-rule-ID namespace is reserved for this pack.
Customer-authored rules must use an organization namespace such as
`acme.advisor.*`.

## Pack versioning

Pack versions follow semver. Bump the version in `metadata.version` when you change rules. Older versions remain available — agents that synced before the bump continue to use the previous revision.

## Framework governance packs

All framework packs share a common set of immutable rules (marked **†**) and mutable warn rules. Immutable rules cannot have their `effect` changed in the UI.

<Callout type="info">
  Because these platforms do not emit AGT-native evidence, all rules in these packs operate on normalized Spctre gateway events rather than on-device policy decisions. Deploy the gateway ingest endpoint and configure the platform's webhook or event stream to send events to `/api/gateway-ingest/{connector}`.
</Callout>

## High-risk connector packs

Hand-authored packs for high-blast-radius third-party connectors: payments, databases, source control, deployment, and support platforms. Unlike the framework and enterprise-platform packs above, these operate on the normalized tool-call parameters (amount, row count, branch name, environment, role) already present in the governed request — no live fraud scoring, query planning, or external lookups. All are `HIGH` risk and require 2 approvals (Security + Compliance) to publish.
