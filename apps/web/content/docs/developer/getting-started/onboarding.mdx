title: Onboarding
description: How the CLI device-approval flow works and what it sets up.

The `spctre init` command runs a device-approval flow to connect your agent to the control plane without storing long-lived credentials in your repo.

## Starting in the browser

Open **Try a sample decision** from your workspace's policy page. Sending an allowed or blocked sample creates example evidence, not a real agent connection.

After the sample, choose one connection method:

- **CLI** is the default for local setup. Install the CLI, approve sign-in during `init`, then sync the workspace. This path does not need a browser-generated setup token.
- **JavaScript** or **HTTP with curl** shows a gateway request after you generate a setup token. Copy the token before leaving; it is shown once.

The page displays one set of instructions at a time and checks automatically for non-sample evidence. **Real agent evidence is flowing** confirms that real evidence arrived. If status checks fail, the page reports the problem and retries automatically.

If preparing the starter policy fails temporarily, choose **Retry starter setup**. A permission error instead explains that a workspace administrator must complete the step. **View starter policy** opens the workspace policy inventory.

## The approval flow

<Steps>
  <Step>
    **Start the flow**

    ```bash
    spctre init \
      --agent my-agent \
      --environment production \
      --workspace my-workspace
    ```

    The CLI calls `POST /api/onboarding/cli/start` and receives a short-lived device code.
  </Step>
  <Step>
    **Approve in the browser**

    The CLI opens `https://<your-control-plane>/onboarding/cli/approve?code=<code>` in your browser. Review the requested token scope (`bundle:read`, `decision:evaluate`, `evidence:write`, `heartbeat:write`) and click **Approve CLI**.
  </Step>
  <Step>
    **Token exchange**

    The CLI polls `POST /api/onboarding/cli/exchange` until the browser approval completes, then receives:

    ```json
    {
      "accessToken": "…",
      "accessTokenExpiresAt": "2026-06-15T12:00:00Z",
      "refreshToken": "…",
      "refreshTokenExpiresAt": "2026-09-15T12:00:00Z",
      "workspaceId": "uuid",
      "workspaceSlug": "my-workspace"
    }
    ```
  </Step>
  <Step>
    **Config written**

    The CLI writes `.spctre/spctre-config.json` with your workspace, agent, and environment details. All subsequent CLI commands read this file automatically.
  </Step>
</Steps>

## Headless / CI environments

Use `--device` to get a code you can approve from a separate browser session:

```bash
spctre init --agent ci-agent --environment staging --device
```

The CLI prints a URL and code. Open the URL in any browser, approve, and the CLI picks up the token automatically.

## Service account tokens

If your organisation provisions service accounts, pass the token directly — no browser approval needed:

```bash
spctre init --token $SPCTRE_SERVICE_TOKEN
```

Or set `SPCTRE_API_TOKEN` in your environment and omit the flag.

## What gets created

| File | Purpose |
|---|---|
| `.spctre/spctre-config.json` | Workspace, agent ID, environment, token |
| `spctre-policy.json` | Downloaded policy bundle (via `sync`) |
| `.spctre/sitecustomize.py` | Python framework adapter (via `watch --framework`) |
