---
title: Audit Ledger
description: What the audit ledger feed contains, event verification, and retention.
---

The **Audit Ledger** is a chronological, hash-chained feed of all platform events — policy publishes, approvals, tokens, identity changes, and ingest records. It provides a tamper-evident, append-only view of what is happening across all agents and workspaces.

## What appears in the ledger

| Entry type | Generated by |
|---|---|
| Ingest record | Agent submitting a decision to the Audit Log |
| Policy publish | Reviewer publishing a branch |
| Escalation created | Gateway queuing a decision |
| Escalation resolved | Reviewer resolving an escalation |
| Policy bundle sync | CLI fetching a new bundle |
| Simulation guidance | Inline simulation guidance recorded for review |
| Guidance disposition | A reviewer recording, editing, or dismissing simulation guidance |
| Token revocation | `spctre revoke` command |
| Alerting trigger | Alerting rule fired |

## Filtering the ledger

The audit ledger supports filtering by:

- **Entry type** — e.g. ingest, policy, escalation
- **Agent** — specific `agentId`
- **Connector** — e.g. `stripe`, `github`
- **Date range** — ISO 8601 from/to
- **Status** — `ALLOW`, `DENY`, `WARN`, `ESCALATE`
- **Risk level** — `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`

## Retention

Audit ledger entries are retained for the period configured in your workspace settings (default: 90 days). Entries older than the retention window are archived and can be exported before deletion.

## Simulation guidance attribution

Recorded simulation guidance uses the `SIMULATION_GUIDANCE` attribution tag, identifying it as system-generated. Human reviewer actions on the guidance are separately attributed to the reviewer's principal ID.

## Programmatic access

```
GET /api/v1/operations
Authorization: Bearer <token>
```

The API returns a paginated feed of audit ledger entries with the same filtering options as the UI.
